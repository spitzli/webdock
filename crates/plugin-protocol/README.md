# Plugin protocol contracts

`Manifest::parse` validates the v2 JSON descriptor, bounds its size and nesting, rejects unknown/privileged fields and duplicate keys, validates immutable image references and declared action/schema relationships, and preserves original bytes for release verification. It accepts declarations independently of installer support. `require_action_only_lifecycle` enforces the current installer's restriction against jobs, dependencies, tables and migrations. `require_host_services` rejects unavailable required service versions; catalog names never imply installed implementations.

`verify_invocation` preserves the existing token format: base64url JSON, a dot, and the Ed25519 signature over the **encoded** JSON segment. It validates exact plugin identity/generation, UUID/project/customer string identity, issued/expiry times and the maximum 60-second lifetime. `customerID` is required and is derived by Core from the admitted project's database owner, never action input. It does not establish current user/project/grant authority. The host must revalidate that authority and the stored customer binding on each call.

`ActionPolicy` implements the common enabled/ready/generation/configuration/project/grant capability checks. It deliberately does not perform the specialized website HTTP authorization deferral: that requires an actual scoped HTTP binding adapter before execution. `validate_value` uses the maintained `jsonschema` library after checking the restricted local schema vocabulary. HTTP/file reference resolution features are disabled. npm-compatible core version ranges use `node-semver`; signatures use `ed25519-dalek`.

The crates do not verify registry release signatures, issue tokens, persist invocations, implement SQL migrations or grant access to host services. Protocol tests include the existing project-notes descriptor and a deterministic signature generated with Node's crypto API from test-only key bytes `[7; 32]`.
