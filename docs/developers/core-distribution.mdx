---
title: "Run the core distribution"
description: "Build the native Rust Core with its React Console and account UI."
---

The current source branch uses one Rust Core to serve the API and the built React Console and account UI. The previous Bun API and Next.js distribution are archived under `legacy/`. Historical published releases describe that retired runtime, not the native candidate.

## Build

```sh
bun install --frozen-lockfile
bun run build:api
bun run build:console
bun run quality
bun run test:distribution
```

The browser artifact is `apps/console/dist`. Set `WEBDOCK_UI_DIST` to that immutable directory when starting Core outside the container. Console, account and protocol surfaces retain their independently configured canonical origins.

```sh
docker build -f deploy/docker/Dockerfile --target core -t webdock-core:local .
docker build -f deploy/docker/Dockerfile --target migrate -t webdock-migrate:local .
```

Additional image targets package `bootstrap-operator`, `agent-control`, `plugin-control` and `plugin-controller` as separately supervised native processes. Product plugin images are built independently with their own Dockerfiles.

## Configure and initialize

Follow [native self-hosting](/developers/self-hosting) and [initial operator setup](/developers/initial-setup). Runtime PostgreSQL credentials are restricted and separate from the offline migrator. Core does not initialize schema at startup. Enable products explicitly; enabling outgoing Mail does not provision an incoming instance.

The current branch provides deployment candidates, not a published native release or production cutover. Retained-data migration, rollback after new writes and outstanding product acceptance must be verified separately.
