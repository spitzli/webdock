# Slim core implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development or executing-plans to implement task-by-task.

**Goal:** Reduce the default admin platform to core services and explicitly installed extensions; remove billing and separate auth providers.
**Architecture:** Provider-neutral core contracts, trusted auth plugins, optional product composition. Keep existing project plugin runtime authority intact.
**Tech Stack:** TypeScript, Elysia, Next.js, PostgreSQL, existing SDKs.
**Spec:** docs/architecture/slim-core.md

## Global constraints
- Preserve live data, authentication security and existing explicit product selection.
- No new billing plugin, payment provider or analytics theme work.
- No production rollout during the refactor.

## Review focus
- Missing module configuration must not enable products.
- Removed billing paths and operations must fail closed, including MCP.
- Clerk must not require construction of the Better Auth provider to verify browser identity.
- Auth rejection, revocation and tenant mapping must preserve current local authorization.
- Existing explicit installation state must retain its meaning.

## Task 1: Remove billing composition
- [x] Trace billing routes, RPC/MCP operations, UI, workers and package dependencies.
- [x] Add regression coverage for unavailable billing surfaces.
- [x] Remove active billing implementation and callers; retain historical migrations/data.
- [x] Run relevant tests and TypeScript checks.

## Task 2: Separate authentication plugins
- [x] Trace existing adapters, provider configuration and runtime callers.
- [x] Put provider configuration/implementations into distinct trusted plugin packages; core exports provider-neutral contracts only.
- [x] Select/load the provider explicitly and lazily, retaining legacy Better Auth defaults without instantiating both providers.
- [x] Test provider selection, validation, identity/revocation behavior and TypeScript consumers.

## Task 3: Empty default core and integration
- [x] Make products opt-in; preserve explicit configuration and safe shutdown preflight.
- [x] Remove remaining product-specific imports from core contracts/bootstrap where practical; document any residual module coupling accurately.
- [x] Update installation schema/docs and add behavioral regression tests.
- [x] Run module/API/Console checks; review combined diff and fix findings.

## Verification and scope

Implementation is verified locally; no production rollout. See `docs/verification/2026-10-17-slim-core.json`. The core API no longer mounts Billing and optional Console product dispatch is lazy. Full removal of legacy product packages from the application distribution remains a separate extraction: shared schema, legacy DTOs and product policy hooks are retained explicitly, rather than claiming they are isolated runtime plugins.
