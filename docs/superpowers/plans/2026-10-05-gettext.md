# Webdock gettext Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans. App translation tasks have disjoint ownership; Root merges catalogs and performs deployment/browser QA.

**Goal:** Localize the complete Webdock product UI with English source/fallback, German and System language selection.
**Architecture:** Shared pure gettext core and request-bound React provider. GNU PO files compile to checked-in JSON; browser/runtime do not parse PO. Host-only preference cookies plus supported weighted Accept-Language resolve the locale, without URL changes or mutable server-global locale.
**Tech Stack:** Existing Next16/React19/Node24, installed GNU gettext1.0 and Python stdlib for development.
**Spec:** `docs/superpowers/specs/2026-10-05-customer-view-and-canvas.md` section4; `packages/i18n/README.md` is the exact integration contract.

## Global constraints
- English literal msgids. German catalogs under packages/i18n/locales/de/{auth,studio,web,cms}.po; shared core.po already exists.
- Translate product UI, metadata, labels, states, accessibility text and user-facing errors; preserve customer-authored content, IDs, enum values, URLs and OAuth signed queries.
- Server components use getRequestI18n(); client components use useI18n(); never a mutable global current locale.
- Language switch refreshes server components without changing the current URL or resetting unsaved Canvas/editor state.
- Host-only preference cookie is display preference, not authentication. All existing access checks remain intact.
- Use msgid() for indirect/static labels so GNU extraction can find them. Unknown provider errors use the translated generic error boundary; don't translate arbitrary customer messages.

## Shared glossary
Workspace → Arbeitsbereich; Tenant → Mandant; Customer → Kunde; Website → Website; Draft → Entwurf; Publish → Veröffentlichen; Preview → Vorschau; Site builder → Site-Builder; Sign in → Anmelden; Sign out → Abmelden; Settings → Einstellungen; Save → Speichern; Cancel → Abbrechen; Remove → Entfernen; Customer view → Kundenansicht; Tenant admin → Mandanten-Admin. Use context or more specific English messages when semantics differ (e.g. Cancel appointment → Termin stornieren).

## Review focus
- A language switch during signed OAuth/2FA must preserve all original query parameters exactly.
- Locale-dependent date/number formatting changes presentation only, never stored values or booking timezone.
- Error state comparisons remain semantic/raw-source comparisons; translate at presentation boundaries.
- Server/client initial locale must agree, and cached responses must not mix users' languages.
- Existing content-locale controls in shared CMS remain separate from UI locale.
