# CMS S3 media implementation plan

> **For agentic workers:** Use superpowers:executing-plans. Never migrate existing stores implicitly.

**Goal:** Give explicitly configured new CMS instances private durable S3 media while preserving CMS media URLs and trash behavior.

**Architecture:** Keep the current local backend as default and use the matching maintained Payload S3 adapter for opt-in instances. The bucket stays private; the existing CMS file route checks visible media metadata and serves verified raster bytes. A forward private PostgreSQL binding records the exact instance/project/environment/destination and rejects a changed backend or adoption of existing local media.

**Tech stack:** Current Next 16.3.8/Payload4 canary37, `@payloadcms/storage-s3` canary37, PostgreSQL, existing MinIO fixture.

**Spec:** `docs/handovers/2026-10-25-s3-managed-storage.md`, CMS/app files section.

## Constraints

- Existing `apps/cms` Vercel Blob and existing production stores remain unchanged.
- Local storage remains default; a complete explicit S3 configuration is required. No ambient credentials or public bucket ACL.
- Bind a pre-provisioned restricted resource to CMS instance, project and explicit environment. A prefix alone is not isolation.
- Keep `/api/media/file/<UUID>.<extension>` URLs. Keep current public-raster policy; do not turn private documents/exports into public files.
- Preserve the existing 10 MiB validated raster limit and soft trash. No S3 deletion when merely trashing a media record.
- Require HTTPS/TLS verification; only an explicit literal-loopback test endpoint may use HTTP.
- No automatic copy, backend switch, old-store cleanup or pre-S3-image rollback for a new S3-backed instance.
- Schema migrations run only through the existing explicit migration job; runtime performs DML binding checks, never DDL.

## Tasks and interfaces

1. **Configuration and binding** — extend `loadCMSConfig` with a discriminated private media config. Add `src/lib/media-storage.ts` helpers for stable non-secret binding fingerprints, native adapter options and private DB registration. Test default preservation, incomplete/untrusted configurations, identity mismatch and rejection of nonempty store adoption before implementation.
2. **Forward media metadata** — add a Payload migration and snapshot for content hashes and adapter prefix fields plus a private binding table. Hook server-derived hashes to validated media bytes; prohibit client changes to internal storage fields. Keep old migrations unchanged and new down operation fail closed.
3. **Read/write integration** — wire the official adapter and its scoped credential/client cache key into `payload.config.ts`; wire `onInit` binding checks. Adapt the existing media file route to use the configured storage handler while retaining metadata visibility/trash checks and verifying actual size/hash/MIME before a public response. No raw S3 URL or signed URL escapes.
4. **Owned acceptance** — use fresh PG and existing MinIO with new owned buckets/users. Upload real raster data, restart the CMS process without local media, retrieve exact bytes through unchanged URLs, prove private bucket and foreign-scope denial, soft trash/restore and explicit hard deletion. Refuse changing destination or enabling S3 over existing local records. Verify old local tests and Next build with build-only fake config.
5. **Operations** — document explicit environment configuration, private resource ownership, unchanged legacy stores, required migrations and measured limits. Record evidence separately from Wasabi and production readiness.

Full source/target migration of an existing store still requires its own inventory, byte/hash/reference/URL checks, write fence and rollback. This opt-in path deliberately refuses that operation.
